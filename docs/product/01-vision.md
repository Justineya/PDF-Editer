# 产品愿景与定位

## 一句话

**ForgePDF**：本地优先、性能优先的全能 PDF 工作台——先做到「打开就快、批注就顺、整理就稳」，最终覆盖专业编辑、OCR、转换、签名与合规能力，对标 Acrobat Pro 级能力集，但不走云订阅路线。

> 工作名暂定 ForgePDF，可后续更名。仓库当前名为 PDF-Editer。

## 目标用户（当前阶段）

| 优先级 | 用户 | 诉求 |
|--------|------|------|
| P0 | **自己（作者本人）** | 日常阅读、批注、整理、编辑、签名、扫描件处理；大文件不卡 |
| P1 | 同类重度个人用户 | 学生/研究者/自由职业者，要桌面级性能与离线 |
| P2（远期） | 小团队 / 内网部署 | 同一套内核上的可选协作与自托管 |

当前决策：**先把「自己天天用」做到极致**，产品化与商业化后置；架构仍按「可演进到全能」设计，避免后期推倒重来。

## 产品原则

1. **性能是功能**：首屏打开、连续翻页、缩放、笔迹延迟是一等指标，不是优化项。
2. **本地优先**：默认文件不出本机；任何云能力必须显式开关。
3. **全能是终局，不是 MVP**：用分阶段交付逼近 Acrobat 能力集，但不在早期假装已全能。
4. **真能力 > 表面能力**：红act 必须删内容流；OCR 必须可检索；编辑要区分「叠加」与「内容流编辑」。
5. **许可干净**：默认 Apache/MIT/BSD 栈；AGPL（MuPDF/iText 等）仅在明确可接受或已购商用时引入。
6. **一个主窗口，一条主路径**：工具按任务分组，避免做成按钮博物馆。

## 终局能力愿景（对标 Acrobat Pro）

| 能力域 | 终局标准 |
|--------|----------|
| 查看与导航 | 大文件流畅；书签/大纲/缩略图/全文搜索；多标签 |
| 批注与审阅 | 高亮/下划线/删除线/便签/绘图/图章；批注面板与导出 |
| 页面组织 | 插入/删除/旋转/提取/合并/拆分/重排/页码 |
| 内容编辑 | 文本内容流编辑 + 图像编辑 + 对象级操作；复杂版式可渐进增强 |
| 表单 | 填写 AcroForm；可视化创建表单域 |
| OCR | 扫描件可检索、可选可编辑双层 PDF |
| 转换 | PDF↔Word/Excel/PPT/图/HTML；质量分档（快/准） |
| 签名 | 手写/图片/证书签名；签名域 |
| 安全与合规 | 加密、权限、证书、**真红act**、元数据清理 |
| 印刷与无障碍 | Preflight / PDF/A·X、无障碍检查（最远期） |
| AI（可选插件） | 摘要、问答、引用页码；本地模型优先 |

## 明确的非目标（至少到 Phase 2 结束前）

- 不做账号体系与强制订阅
- 不做「上传到我们的服务器才能用」的核心路径
- 不做 Creative Cloud / 企业 SSO（可留扩展点）
- 不把 Excalidraw 式白板当成 PDF 内核
- 不为追功能列表而引入 AGPL 污染主程序

## 成功标准（作者自用）

| 指标 | 目标 |
|------|------|
| 打开 200 页图文 PDF 到可阅读 | ≤ 1.5s（SSD，冷启动另计） |
| 60fps 平移/缩放（典型文档） | 主观流畅，掉帧可感知次数≈0 |
| 手写批注端到端延迟 | ≤ 20ms 感知 |
| 日活路径 | 打开 → 批注/整理/导出 无需查文档 |
| 崩溃率 | 正常使用周崩溃 = 0 |

## 与竞品的关系

| 产品 | 我们学什么 | 我们不学什么 |
|------|------------|--------------|
| Adobe Acrobat | 能力完整度、专业工具语义、真编辑/红act 标准 | 订阅绑架、重安装、AI 另收费 |
| WPS PDF | 中文场景、转换入口、性价比工具聚合 | 广告/会员墙驱动的交互 |
| Stirling-PDF | 工具箱 completeness、API/自动化思维 | 纯「工具按钮墙」、弱编辑体验 |
| PDF.js 生态 | Web 渲染与批注扩展经验 | 把 Web 渲染当成唯一终局引擎 |
