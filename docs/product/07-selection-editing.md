# 选择与编辑：问题诊断、对标学习与待开发功能点

> 状态：设计 backlog + **2026-09 实现进度已回写 §10**（A/C/D 已冒烟；E 部分）  
> 背景：早期「选择」「编辑」模式可用度差；本文对齐业界交互，并跟踪落地。  
> **本文不宣称短期做到 Acrobat 级自动重排真编辑。**

---

## 0. 一句话结论

| 模式 | 用户期望 | 我们现在做的 | 正确方向 |
|------|----------|--------------|----------|
| **选择** | 像 Word/浏览器一样**按字选中**，复制、高亮 | 在透明层上**拖框**，生成一块黄高亮 | PDF.js **Text Layer** + DOM Selection + 浮动工具条 |
| **编辑** | 点中原文改字、改图、改位置 | 侧栏填字 → **点击空白处盖一层新字** | 分两档：**对象层编辑（白盖+重绘）** → 后期 **内容流真编辑** |

选择废掉的根因不是「缺功能按钮」，而是**根本没有可选文本层**；编辑不好用的根因是**没有对象模型与选中态**，只有「戳一下放贴纸」。

## 1. 当前实现诊断（对照代码）

### 1.1 选择模式（`mode === 'select'`）

现实现：`pointerdown` 记起点 → 拖出矩形 → `pointerup` 写入 `kind: 'highlight'` 批注。

失败点：

1. **无 Text Layer**：页面只有 canvas 像素，DOM 里没有可选 `<span>`，无法 `getSelection()`。
2. **与批注模式撞车**：选择 = 区域高亮，用户以为是「选字」却得到「涂黄」。
3. **不能复制**：没有选中字符串，剪贴板无内容。
4. **不能跨行/跨页**：框选是几何矩形，不是字形矩形序列。
5. **扫描件无提示**：无文本层时仍可拖框，用户以为选中了字。

产品文档 `05-ux-ia.md` 已写「文本选择 `T`：选字复制、触发批注」，**实现未兑现**。

### 1.2 编辑模式（`mode === 'edit'`）

现实现：侧栏输入框 + 点击页面 `onAddOverlayText`；另有插图、全页水印。

失败点：

1. **不能改原文**：只能在原文上面再盖一层。
2. **无选中 / 无句柄**：放完就散落，不能点选、拖动、改字号、对齐。
3. **放置即提交**：没有预览框、没有「确认放置」，误点即脏。
4. **字体无关**：新字用系统/嵌入字体，与原文视觉割裂。
5. **无删除原文手段**：连「白盖遮字」也未做成一等对象工具（红act入口另开，语义混乱）。

### 1.3 架构缺口（必须先补）

```
当前：  PDF 字节 → canvas 渲染 → 透明 pointer overlay（框选/戳点）
应对：  PDF 字节 → canvas 渲染
                 → TextLayer（可选、可复制）
                 → AnnotationLayer（批注）
                 → EditObjectLayer（可点选的叠加对象：文本框/图/白盖）
                 → InteractionController（按 mode 切换 pointer-events）
```

## 2. 业界怎么做（要学的模式，不是抄 UI 皮肤）

### 2.1 文本选择（Chrome PDF / PDF.js / Foxit / Acrobat Reader）

共同模式：

1. 渲染页后叠一层**透明文字层**（位置与 canvas 字形对齐，`color: transparent`）。
2. 用户用鼠标拖选 → 浏览器原生 Selection。
3. `mouseup` / `pointerup` 后：
   - `selection.toString()` → 复制/搜索
   - `range.getClientRects()` → 多行矩形
   - 转 PDF 坐标 → 写 Highlight / Underline / Strikeout
4. **浮动工具条**（Foxit / Acrobat）：复制 · 高亮 · 下划线 · 删除线 ·（可选）书签 / 搜索。
5. 无文本层 / OCR 前：禁用选字，提示「本页无可选文字」，提供区域工具或 OCR。

Nutrient / PDF.js 社区实践要点：

- 坐标：`clientRect - pageDiv.getBoundingClientRect()` → `viewport.convertToPdfPoint`
- 一行选择可产生多个 rect；跨页要按 page 拆分
- `tool === 'select'`：弹出工具条；`tool === 'highlight'`：松手即建批注

**要学：Text Layer + Selection → Floating Bar；不要学：把选择做成框选高亮。**

### 2.2 区域选择（Acrobat / Foxit「选择工具」的另一半）

专业软件通常拆成：

| 工具 | 行为 |
|------|------|
| 选择文字 | 字形级 |
| 选择截图 / 矩形 | 框选复制为图片 |
| 选择对象（编辑模式） | 点中文本块/图/路径 |

我们 Phase A 只做「选文字」；矩形截图、对象选择分别进后续包。

### 2.3 轻编辑（WPS / Foxit / Acrobat「添加文本」）

实用路径（多数会员级产品的日常编辑）：

1. **添加文本框**：点击放置 → 出现可编辑框 → 失焦写入叠加层。
2. **白盖/涂改液**：框选区域填白（或背景色）再写新字 —— **视觉上像改了**，内容流里旧字仍在（需在 UI 标明「覆盖编辑」）。
3. **移动/缩放对象**：选中后八向句柄 + Delete。
4. **插入图片 / 水印**：作为对象，可改透明度与层级。

### 2.4 真编辑（Acrobat Edit Text / PDFEdit PDEText）

Acrobat 改的是 **page content stream**（`PDEText` 等），不是 Word：

- 文本常是「按 run / 按 glyph」画的，不是段落。
- 子集字体缺字形 → 替换失败或换字。
- 多栏/环绕时自动重排（Auto-adjust Layout）是高难度、仍有限制的能力。

**ForgePDF 定位：**

- **近中期交付**：选择正确 + 对象层轻编辑（覆盖编辑）做到「日用够用」。
- **真编辑**：单独阶段，先支持「简单单行/单块替换」，复杂版式明确降级为框编辑。

## 3. 产品原则（写进交互规范）

1. **选择 ≠ 批注工具**。选择模式默认不涂黄；涂黄是工具条动作或批注模式。
2. **编辑分两档，文案诚实**：
   - 「覆盖编辑」= 白盖 + 新文本/图（可撤销、可导出）
   - 「修改原文」= 改内容流（已提供区域擦除+重写切片；复杂版式可能失败，可降级覆盖编辑）
3. **无文本层要说人话**：状态栏/空态提示，并给「区域高亮 / OCR」出口。
4. **pointer-events 按模式互斥**：选字时 TextLayer 可点；批注/红act 时关掉选字；编辑时走对象层。
5. **一次只做一个主任务**：第一视口工具条只暴露当前模式 3～5 个动作。

## 4. 待开发功能点（Backlog）

优先级：`P0` 阻断体验 → `P1` 日用闭环 → `P2` 编辑可用 → `P3` 真编辑/进阶。

### 包 A — 真正的文本选择（P0，优先做）

| ID | 功能点 | 说明 | 验收 |
|----|--------|------|------|
| A1 | PDF.js Text Layer 渲染 | 每页 canvas 上叠对齐文字层；缩放/旋转同步 | 英文/中文样例可拖选单字与多行 |
| A2 | 模式指针策略 | `select`：textLayer 可交互；其他模式关闭或 `user-select:none` | 批注拖框不再误选文字 |
| A3 | 复制选中文本 | `Ctrl/Cmd+C` + 工具条「复制」；写入剪贴板 | 粘贴到记事本内容正确（含换行近似） |
| A4 | 选择矩形提取 | `getClientRects` → PDF 坐标 `rects[]` | 跨行高亮贴合字形，而非整页大框 |
| A5 | 选区浮动工具条 | 复制 / 高亮 / 下划线 / 删除线 | 松手后条出现在选区旁；Esc 关闭；点动作后清除选区 |
| A6 | 无文本层降级 | 检测 `getTextContent` 空 → 提示 + 「改用区域工具」 | 扫描样例不假装可选字 |
| A7 | 搜索命中与选择联动 | 已有搜索结果可「选中并滚动到」 | 点击结果 = 页内闪烁 + 可选复制 |

**明确不做（本包）：** 跨页连续选择的完美合并（可先单页）；右键菜单全套。

## 5. 建议实施顺序（技术依赖）

```
A1 TextLayer
 → A2 指针策略
 → A3 复制 + A5 浮动条
 → A4/B1 选字高亮
 → B4 区域高亮改名分离
 → C1 对象模型
 → C2/C3 文本框可编辑可拖
 → C5/D1 白盖+替换工作流
 → F1 Undo
 →（引擎具备后）E1/E2 真编辑
```

**第一个可感知胜利：** 用户打开任意带文字 PDF → 切到「选择文字」→ 拖选 → Ctrl+C 粘出正确文字 → 点「高亮」得到贴合字的标注。  
做到这一点，「选择是废的」才能被推翻。

**第二个可感知胜利：** 编辑模式点一下 → 出现文本框可输入 → 拖到正确位置 → 导出后仍在。  
再往后才是「改原文」。

## 7. 技术要点（实现备忘）

1. **PDF.js**：`page.getTextContent()` + `TextLayer`（或自建绝对定位 span）；worker 已稳定在 4.10 路径上继续。
2. **坐标**：统一存 PDF 用户空间；渲染时用 viewport 转换；注意 Y 轴翻转。
3. **导出**：批注走 annotation / 外观流；编辑对象用 pdf-lib 画白矩形 + `drawText` / 嵌图（覆盖路径）；真编辑需 PDFium/商业库或深度内容流改写。
4. **中文**：TextLayer 选字依赖 PDF 自带 ToUnicode；缺映射时复制乱码 → 提示「本页编码不完整」并记入 E 包。
5. **与现有 `select` 框选逻辑**：迁移为批注模式的「区域高亮」，避免两套黄框。
